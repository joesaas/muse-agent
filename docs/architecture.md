# muse-agent 总架构

一句话：**照 Muse 的设计思想，用一套模块化、可长期维护的骨架，复刻一个属于自己的 super agent；先把模块、接口和数据流做对，底层执行用最小实现/适配层占位。**

本项目是学习性复刻：借鉴的是 Muse 公开可归纳的设计（19 章设计站），不是对 Muse 未公开内部实现的断言。凡设计站里证据等级为「未证实 / 无法核实」的部分，本项目只采用其设计思想，不声称与 Muse 内部一致。

## 技术选型

| 选择 | 决定 | 理由 |
|---|---|---|
| 语言 | Python 3.11+ | 生态通用、单文件可读、适合长期维护 |
| 依赖 | **运行时零第三方依赖**（仅标准库） | 供应链最小、十年后还能跑；供应商 SDK 等都进 adapter，不进核心 |
| 模型 | 默认 MockProvider（离线、确定性） | 无 Key 即可运行与测试全系统 |
| 存储 | 纯文本文件（md / json / toml） | 用户拥有、可读、可备份、可迁移 |
| 测试 | unittest（标准库） | 零安装成本 |

## 分层

```
前端层      CLI（本仓库） · 聊天端 / API（未来，只做入口与渲染）
              │  build_session()
运行时层    runtime/session（唯一装配点） · runtime/agent（Agent 循环）
              │  事件总线 core/events（消息 / cron / hooks / 子代理交回）
能力层      llm · prompts · context（含压缩与恢复） · memory
            skills · tools · connectors · subagents
治理层      approval（HITL 分级审批） · security（凭证按名取用、脱敏）
            scheduling（cron / hooks） · goals（目标与跟踪）
地基层      core（数据契约 + 事件 + 错误） · identity（站立文件） · home（目录布局）
            config（环境 + config.toml，秘密永不进配置）
```

依赖方向只有一条规矩：**上层可以依赖下层，同层经 core 契约通信，core 不依赖任何业务包。**

## 一次交互的流程（对照设计站 ch19）

1. 前端收到用户消息 → `build_session()`（或复用已有 Session）
2. Session 组装：home 布局 → 身份文件 → 精选记忆 → skills 索引 → tools 规格 → 系统提示词分段拼装 → 上下文窗口（系统提示词钉首位）
3. `Agent.run_turn()` 进入内圈循环，每步：
   - 检查打断标记（用户打断优先）
   - 上下文超预算 → 压缩中段旧消息为一条摘要
   - 问 LLM（messages + tool specs）
   - 模型给工具调用 → 按 risk 过审批闸门 → 执行 → 结果以 tool 消息回注 → 继续循环
   - 模型给最终文本 → 落上下文、存恢复快照、发 `turn.finished` 事件、返回前端
4. 外圈：cron 到期、hook 命中、子代理完成，都以事件唤醒同一个循环，不另开智能通道
5. 子代理：需要并行/隔离时派生，拿父上下文的**全量快照副本** + 任务简报独立运行，结果交回主代理

## 设计原则（长期维护口径）

1. **模块只经接口说话**：跨模块只流通 core 的数据类；换实现不换调用方。
2. **数据归用户**：记忆、身份、目标、skills 都是用户目录里的纯文本，代码可替换，数据不迁移格式。
3. **提示词是注册表**：分段、编号、有序、可禁用、可单测，不是一整段不可维护的字符串。
4. **能力是数据**：skill 是 Markdown，工具是注册项，连接器是适配器——新增能力不改运行时。
5. **治理内建**：审批、凭证、脱敏是模块，不是约定；无人值守默认拒绝需审批动作。
6. **可观测与可恢复内建**：每步事件 + 快照，崩溃后能续、事后能查。
7. **不追求速度，追求边界正确**：先模块与契约，后优化与规模。

## 当前状态与诚实边界

- 已实现最小可运行版：循环、工具、审批、压缩、记忆、skills、子代理、调度判定、目标跟踪、CLI 与 demo，含单测。
- 仅接口/占位：真实模型仅 OpenAI 兼容 adapter（够用但无流式/缓存优化）；连接器仅参考实现；surrogate 凭证是集成缝；调度只判定不托管进程；子代理是进程内执行。
- 未做：多端前端、向量检索、LLM 摘要器、跨进程事件传输——都在 roadmap 里，接口已留好。
